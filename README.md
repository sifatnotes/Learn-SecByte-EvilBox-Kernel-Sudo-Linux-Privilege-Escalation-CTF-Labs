# Learn SecByte EvilBox, Kernel, Sudo & Linux Privilege Escalation CTF Labs

Hands-on cybersecurity and CTF lab collection covering EvilBox target discovery, Linux hardening, attack-chain analysis, SSH pivoting, backdoors, kernel security, SUID binaries, sudo misconfigurations, and privilege escalation concepts.

This collection is intended for cybersecurity students, CTF players, penetration testers, SOC analysts, and security learners practicing security assessment techniques in authorized environments.

## Introduction

The EvilBox and Linux-focused labs provide practical exercises across reconnaissance, attack-chain analysis, system hardening, pivoting, authentication weaknesses, and privilege escalation.

The collection progresses from target discovery and defensive hardening toward Linux privilege escalation and post-compromise concepts.

Use these resources only against intentionally vulnerable or explicitly authorized systems.

## Learning Path

A practical progression is:

1. Start with **EvilBox Target Discovery** to practice initial reconnaissance.
2. Study **EvilBox Hardening Lab** to understand defensive controls.
3. Review **EvilBox Attack Chain Review** to connect individual security weaknesses into an attack path.
4. Practice **EvilBox Flag Forge** as a CTF-style exercise.
5. Continue with **Evil Root Unlocked** for Linux privilege-escalation concepts.
6. Explore **Bins of Power**, **Sudo Slipstream 2**, and **Kernel Whisper** for additional Linux escalation scenarios.
7. Study **EvilBox Pivot** and **EvilBox SSH Pivot** to understand pivoting concepts.
8. Finish with **Evil Auth Linux Backdoor** and review the defensive implications.
9. Use **Chronos Time to Decode** for supplementary decoding practice.

## How to Use the Labs

1. Open a lab using the direct link above.
2. Confirm that the target is part of an authorized training environment.
3. Read the objectives before beginning.
4. Perform reconnaissance and document your findings.
5. Identify relevant services, configurations, binaries, or authentication mechanisms.
6. Test security weaknesses only within the permitted environment.
7. Record the techniques, evidence, and lessons learned.
8. Consider the corresponding defensive mitigation after completing each exercise.
